# VESC ESC Workbench

Уточнена схема перемотанного статора: по предоставленному рисунку это 12 пазов,
4 полюса, шаг катушки 3 паза. Это поддерживает `ratio=2`. Пользователь подтвердил
правильное соединение треугольником; вопрос соединения закрыт.
[Разбор схемы статора](docs/stator-winding-20260912.md).

Офлайн-сравнение HFI и выравнивания полем выявило недостаток измерений в одном
положении. Периодическая модель хорошо подгоняет имеющиеся точки, но проверка
с исключением позиции даёт ошибку до 6,61 градуса: коррекция не применяется.
[Расчёт и следующий контроль](profiles/offset-method-comparison-20260912/README.md).

Получен повторяемый результат оффсета: **350,27° / 170,27°** при `ratio=2`,

В контроллер результат не записан: требуется проверка в другом положении ротора.
[Измеренный оффсет и исходные данные](profiles/synrm-as5048a-offset-measured-20260912/README.md).

Проведена одна физическая проба фиксированного угла: команда 0,5 А на 40 мс.
Ток зарегистрирован, но запись прервана проверкой ERPM; исходные настройки
восстановлены, ток нулевой. [Результат физической пробы](logs/locked-physical-probe-20260912-03/REPORT.md).
Это не калибровка оффсета. Общая блокировка вращения остаётся включённой;
отдельный режим допускает только одну строго заданную короткую пробу с защитными
пределами и восстановлением, а не произвольные команды.

Пользователь подтвердил механическую фиксацию ротора. В `config/bench-fixture.json`
записано состояние `locked`: UART-клиент этого проекта блокирует команды вращения,
измерительные терминальные команды и запись конфигураций. Чтение и нулевой ток
остаются доступны. Другие приложения и старые отдельные скрипты эта блокировка
не контролирует. Снимать её можно только после подтверждения снятия фиксатора.

Подготовлены офлайн-план, симуляция и анализ измерений осей индуктивности:
[Locked-rotor calibration](docs/locked-rotor-calibration-20260912.md).
Реальный сбор импульсных измерений пока не подключён. Команда `simulate` не
подключается к контроллеру и не выдаёт действительную калибровку мотора.

Что уже есть:

## Быстрый старт

Создать локальный конфиг:

```powershell
Copy-Item .\config\settings.example.toml .\config\settings.toml
```

Если Python установлен в системе:

```powershell
.\scripts\setup.ps1
.\.venv\Scripts\vesc-workbench.exe status
```

Если системного Python нет, `scripts\setup.ps1` сам возьмет bundled Python Codex.

```powershell
.\scripts\setup.ps1
```

## Поток конфигураций

1. Кладем новые XML-профили в `vesc-test-profiles\<profile-name>\`.
2. Внутри папки профиля ожидаются `vesc_mcconf.xml` и/или `vesc_appconf.xml`.
2. Проверяем и переносим их в staging:

```powershell
.\.venv\Scripts\vesc-workbench.exe scan-configs
```

3. Смотрим, что будет применено:

```powershell
.\.venv\Scripts\vesc-workbench.exe apply-config <bundle-id>
```

По умолчанию это dry-run. Реальные backend-и должны добавляться отдельно и требовать `--armed`.

Непрерывный режим для автоматической подхватки новых XML:

```powershell
.\.venv\Scripts\vesc-workbench.exe scan-configs --no-once --interval 2 --auto-apply
```

С текущими настройками `--auto-apply` тоже dry-run: он создает запись применения, но не пишет в ESC.

## AS5600 + ESP8266 Hall

Кастомный датчик подключается к VESC как обычные Hall sensors, не как ABI/SPI encoder. Подробности: [docs/as5600-esp-hall.md](docs/as5600-esp-hall.md).

Проверить raw debug с ESP8266:

```powershell
.\.venv\Scripts\vesc-workbench.exe esp-hall-monitor --port COM6 --seconds 20
```

Новые профили `14`-`27` используют Hall table, снятую в VESC Tool:

```text
[255, 22, 90, 186, 162, 123, 43, 255]
```

Начинать лучше с `22_hall_esp_detected_uart_pp7_limited_sl1500`, затем `23`, `24`, `27`.

## Безопасный тест тока

Начальный сценарий из передаточного документа:

```powershell
.\.venv\Scripts\vesc-workbench.exe test-current --port COM3 --armed --steps 0.5,1.0,1.5 --max-erpm 1000
```

Старый совместимый скрипт тоже оставлен:

```powershell
.\.venv\Scripts\python.exe .\vesc_autotest.py test --port COM3 --armed --steps 0.5,1.0,1.5 --max-erpm 1000
```

Перед физическим тестом VESC Tool должен быть закрыт, мотор закреплен, а физическое отключение питания ESC должно быть под рукой.

## Автоматический перебор прямого энкодера

Подготовлен безопасный первый контур автоматизации: он создаёт очередь из raw-backup,
записывает каждый вариант, считывает его обратно для проверки, выполняет малый
UART-тест и сохраняет телеметрию с оценкой. До появления нового датчика он работает
только в dry-run; после установки потребуется один ручной Motor Detection + Encoder
Detection, чтобы снять эталонный backup.

Матрица первого прохода находится в
[config/direct-encoder-autotune.json](config/direct-encoder-autotune.json),
а подробный порядок запуска — в
[docs/autotune.md](docs/autotune.md).
