# Совместная работа

Репозиторий содержит исходный код, тесты, документацию и версии профилей. Журналы
физических испытаний, сырые резервные копии ESC и локальные состояния стенда
остаются на компьютере оператора. Не коммитьте токены, личные пути и результаты
непроверенных аппаратных испытаний как подтвержденные характеристики мотора.

## На каждом компьютере

```powershell
git clone https://github.com/Juanbod/vesc-motor-workbench.git
cd vesc-motor-workbench
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

Создайте локальный `config/settings.toml` на основе
`config/settings.example.toml` и задайте свои COM-порт и путь к VESC Tool.
Примеры конфигурации не дают разрешения на подключение и вращение конкретного
стенда. Программы управления мотором требуют проверенного локального состояния
оборудования и отдельного физического допуска на каждом компьютере.

## Два разработчика и два Codex

Каждый работает в собственном клоне и в отдельной ветке:

```powershell
git switch -c feature/short-description
# работа и тесты
git add -A
git commit -m "Describe the change"
git push -u origin feature/short-description
```

Откройте pull request в `main`; второй участник просматривает изменения и
принимает их после проверки тестов. Перед новым изменением обновляйте `main`
через `git pull --ff-only`. Одновременное редактирование одной ветки двумя
агентами не требуется; общая история объединяется через pull requests.
