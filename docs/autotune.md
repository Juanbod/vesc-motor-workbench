# Автоматический стенд подбора конфигураций

Для нового прямого AS5048A используйте `bench` и
[актуальную инструкцию](encoder-bench.md). Описанная ниже `autotune-run` является
ранней заготовкой: её оценка по максимуму eRPM и штрафу Id не подходит для
выбора конфигурации текущего реактивного ротора.

Стенд перебирает только небольшую, заранее заданную матрицу. Он не изменяет
физические параметры, найденные VESC Tool: сопротивление и индуктивность обмоток,
потокосцепление, PI-регуляторы тока, offset энкодера, ratio, режим порта датчика и
параметры коммутации. Именно эти величины должны прийти из Motor Detection и Encoder
Detection: при такой базе мотор уже уверенно вращается во время детекции.

Первый проход меняет четыре подтверждённо сериализуемых поля для MKS ESC 84/100 HP
с firmware 6.02:

- ограничение фазного тока;
- ограничение входного тока;
- абсолютное ограничение тока;
- `foc_mtpa_mode` (выключен или включен).

`foc_fw_current_max`, duty начала field weakening, его коэффициенты, режим порта,
ratio и offset пока не входят в автоматическое изменение. Их бинарные смещения нужно
сначала подтвердить сравнением двух raw-backup, где вручную меняется ровно один
параметр. Это защищает от записи не в то поле.

## Что готово сейчас

1. [config/direct-encoder-autotune.json](../config/direct-encoder-autotune.json) —
   первая матрица MTPA и тока: 25 A без MTPA, 25 A с MTPA, 50 A с MTPA.
2. `generate-autotune-queue` создаёт отдельные бинарные профили из эталонной
   конфигурации и сохраняет, какие поля были заменены.
3. `autotune-run` записывает один motor profile, считывает его обратно и сверяет
   SHA-256, затем выполняет ступени тока по UART.
4. Для каждого профиля создаётся CSV с eRPM, Id, Iq, фазным/входным током, duty,
   напряжением и температурами. Общий `summary.csv` содержит оценку.
5. При fault, скачке eRPM, превышении тока/температуры/duty тест немедленно
   выключает ток и не переходит к следующему профилю.

## Порядок после установки датчика

1. Подключить MT6816 или AS5048A напрямую к sensor port и выбрать его тип в VESC Tool.
2. Выполнить Motor Detection; не менять автоматически найденные физические параметры.
3. Выполнить Encoder Detection, проверить направление, сохранить motor configuration.
4. Снять эталонную копию без VESC Tool:

```powershell
.\.venv\Scripts\vesc-workbench.exe backup-raw-config --port COM10 --name direct-encoder-detected
```

5. Создать очередь из новой копии:

```powershell
.\.venv\Scripts\vesc-workbench.exe generate-autotune-queue `
  .\raw-config-backups\<имя-нового-backup> `
  .\config\direct-encoder-autotune.json `
  --output-dir .\autotune-queue
```

6. Проверить план без доступа к ESC:

```powershell
.\.venv\Scripts\vesc-workbench.exe autotune-run `
  .\autotune-queue `
  .\config\direct-encoder-autotune.json
```

7. Закрепить мотор, закрыть VESC Tool, подготовить физическое отключение питания.
   Запустить первые три профиля:

```powershell
.\.venv\Scripts\vesc-workbench.exe autotune-run `
  .\autotune-queue `
  .\config\direct-encoder-autotune.json `
  --port COM10 --max-profiles 3 --armed
```

После первого успешного прохода в `config/direct-encoder-autotune.json` задаётся
`expected_direction` как `1` или `-1`, соответствующий нормальному направлению. Тогда
следующие прогоны автоматически забракуют профиль, который запускает мотор обратно.

## Как выбирается лучший профиль

Базовая оценка повышается с максимальным устойчивым eRPM и уменьшается при большом
Id и duty. Любая ошибка VESC, неверное направление или срабатывание защиты даёт
крупный штраф. Это ранжирование не заменяет оценку тяги под реальной нагрузкой, но
честно отсекает нестабильные варианты и оставляет короткий список для дорожного
испытания.
