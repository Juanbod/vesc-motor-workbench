# Передача работы: экспериментальный реактивный мотор + MKS ESC / VESC Tool

Дата передачи: 2026-08-11. Язык работы: русский.

## Цель

Настроить необычный мотор на MKS ESC 84100HP через VESC Tool и автоматизировать безопасные тесты с ПК.

## Конструкция мотора

- Основа: переделанный outrunner BLDC.
- Ротор: 4 стальные пластины вместо постоянных магнитов; рабочая гипотеза — синхронный реактивный мотор (SynRM), не обычный PMSM/BLDC.
- Статор: 12 зубьев, распределённая трёхфазная обмотка, соединение треугольником.
- Шаг катушки: из паза 1 в 4.
- Рабочая гипотеза: 4 полюса, 2 пары полюсов. Поле `si_motor_poles` в рабочем XML исправлялось на 4; само FOC не использует его для электрического угла.

## Результаты VESC Tool Detection

Скриншот детектора дал:

- Motor R: **13.39 mΩ**
- Motor L: **22.33 µH**
- Lq − Ld: **14.54 µH**
- Flux linkage λ: **0.044 mWb**
- Current-controller KP: **0.0223**
- Current-controller KI: **13.39**
- Observer Gain (UI): **10000 × 1M**, в XML `1e+10`

Из L и Lq−Ld: приблизительно `Ld = 15.06 µH`, `Lq = 29.60 µH`. Сильная салентность подтверждает реактивную природу. λ почти нулевое, поэтому обычный sensorless observer плохо подходит, особенно на старте и при переходе HFI → observer.

## Важные выводы

1. Штатный VESC FOC не является частотником для короткозамкнутого асинхронного мотора: не следует выдавать любой из XML-профилей за настоящий V/f (синус + V/f + скольжение).
2. HFI-профили дали лучший субъективный результат. Профиль **04_hfi_medium** был признан лучшим в ручном тесте.
3. Профили 03–04 работали при ~5% газа и около 11 А; при увеличении газа слышен срыв синхронизации.
4. Режим ADC Duty был заменён на ADC Current в обычных профилях: `app_adc_conf.ctrl_type = 1`. Ранее `ctrl_type = 9` (Duty) давал плохо контролируемый ток.
5. Во время автотеста потенциометр/ADC конфликтует с UART-командой и мгновенно перезаписывает команду тока. Для автоматики создан отдельный UART-only профиль.
6. Абсолютный энкодер на валу предпочтителен HFI: магнитный AS5047/MA782 или аналог при подтверждённой поддержке текущей прошивкой. Он должен существенно улучшить старт и устойчивость. Нужны калибровка угла и проверка encoder ratio для 2 пар полюсов.

## Профили

`profiles/` содержит XML-пары. Основные:

- `00_autotest_profile04_uart` — фактически последний загруженный на ESC профиль. Моторная часть = профиль 04, `app_to_use = 3` (UART); потенциометр отключён намеренно.
- `04_hfi_medium` — лучший ручной профиль: HFI mode 3, MTPA off, HFI start/run/max = 10/3/4 V, gain 0.25, HFI до 1500 eRPM.
- `03_hfi_soft` — HFI 6/2/3 V, gain 0.15, HFI до 1000 eRPM.
- `07–09` — варианты увеличения диапазона HFI / снижения шума.
- `10–13` — варианты встроенных режимов HFI V2–V5. Их нужно применять только если соответствующий режим поддержан UI/прошивкой.

Все старые профили держат исходные пределы ESC: 77.45 A фазного, 100 A входного, 116.17 A absolute. Это не безопасные испытательные токи; для ручных тестов газ давать очень мало.

## Последний автоматический тест: критичный результат

Выполнен на `00_autotest_profile04_uart` через COM3, питание 24.5 V. Скрипт задал первую ступень 3 A; 5/8/11 A не были выполнены, потому что тест аварийно остановился.

Наблюдения:

- Команда 3 A давала Iq примерно 1–2.9 A.
- eRPM резко колебался по знаку: 37, −1962, 939, −1607 и т.п.
- Стоп сработал на **−4481 eRPM** (настроенный предел был ±3000 eRPM).
- `finally` скрипта отправил 0 A; последующее чтение подтвердило 0 eRPM, 0 A, duty 0.

Вывод: на текущем профиле 04 в UART-тесте наблюдается реальная потеря синхронизации уже около 3 A. Не продолжать поднимать ток до доработки автоматики/профиля либо установки энкодера.

## Python Autotest

- Python: **3.13.15**.
- pyserial: **3.5**.
- VESC: `COM3`, USB Serial Device.
- Главный файл: `vesc_autotest.py`.
- Сценарий корректно читает стандартный VESC UART GET_VALUES и посылает COMM_SET_CURRENT.
- Скрипт по умолчанию не движет мотор без `--armed`; на завершении отправляет 0 A.
- Есть monitor, test, compare CSV.

### Что улучшить в коде до следующего физического теста

1. Добавить плавный рост UART-current (например 0.25–0.5 A шагами), а не мгновенные ступени.
2. Ввести стоп по резкому изменению eRPM между выборками, например >500 eRPM/50 ms.
3. Установить консервативный предел `abs(eRPM) <= 1000` на начальных тестах; прежние 3000 были слишком высокими.
4. Записывать причину аварийной остановки в CSV отдельной строкой/файлом.
5. Полную смену FOC-параметров из XML по UART не реализовывать без считывания точной версии firmware и совместимого бинарного config serializer. Временные лимиты возможно посылать через `COMM_SET_MCCONF_TEMP`, но это также требует аккуратного кодирования и сначала должно быть проверено без нагрузки.

## Безопасность

- Вал без нагрузки, мотор закреплён.
- Доступна физическая кнопка отключения питания ESC. USB не аварийный стоп.
- Перед Python-тестом VESC Tool должен быть закрыт, иначе COM3 занят.
- Не запускать снова текущий профиль 04 в UART автотесте с током 3 A до улучшения ограничителей теста.
- При треске/колебании/росте скорости — физически отключить питание.

## Структура папки

- `profiles/` — все сгенерированные конфигурации.
- `source-configs-current/` — текущие файлы из Desktop `vesc conf`; это НЕ гарантированно исходная заводская версия, а текущий рабочий снимок после правок.
- `vesc_autotest.py` — тестовый Python-клиент.
- `test-autotest-04.csv` — лог аварийно остановленного реального теста.
- `generate-vesc-test-profiles.ps1` — генератор XML-профилей.

## Рекомендуемый следующий шаг

Сначала отредактировать `vesc_autotest.py` по пяти пунктам выше и сделать один тест 0.5 → 1.0 → 1.5 A с ограничением ±1000 eRPM. Если синхронизация сохраняется плохо, перейти к монтажу энкодера, а не продолжать перебирать HFI.
